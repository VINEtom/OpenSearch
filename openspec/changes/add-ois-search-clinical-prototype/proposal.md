## Why

患者资料、诊断与单据、治疗计划分散在 PMS、EMR、RVS 中，工作人员需要从一个入口找到记录，也需要按明确的临床条件找到患者。第一版用三个实际的 PostgreSQL 原型库和虚构数据验证搜索、条件筛选、关联追溯及详情定位。

## What Changes

- 提供全局搜索，覆盖患者、诊断、计划申请单、治疗计划和其他单据，展示来源、患者身份及命中内容。
- 提供临床条件筛选，条件包括诊断、确认状态、诊断日期、年龄、性别、是否有关联计划；结果按患者汇总，并展示匹配依据。
- 建立“患者 → 具体诊断 → 计划申请单 → 治疗计划”的明确关联，按这一关联判断某个诊断是否已有计划。
- 使用独立的 PMS、EMR、RVS 原型数据库保存业务样例，手动同步到 OpenSearch，验证新增、修改、删除后的结果变化。
- 提供原型内的患者与记录详情、关联跳转、命中定位和返回状态保留。
- 形成需求、数据设计、交互流程及测试文档。验收覆盖跨来源检索、诊断条件组合、关联准确性、患者去重、数据更新和失败提示。

## Capabilities

### New Capabilities

- `ois-global-search`: 多来源业务记录搜索、结果分类、命中片段和详情定位。
- `ois-clinical-patient-filter`: 基于结构化诊断及其关联计划筛选患者，展示可追溯的匹配依据。
- `ois-search-prototype-data`: 三个原型数据库、关联校验、手动索引同步及最新详情读取。

### Modified Capabilities

无。

## Impact

- 规划产物位于本 change，面向使用者的文档位于 `docs/`。
- 原型采用 React/Umi、PostgreSQL 和 OpenSearch，在当前独立 Git 仓库中实现；真实详情读取由轻量本地数据访问层支撑。
- 当前交付为规划文档；后续原型使用自己的数据库、索引及配置，数据库凭据及运行数据不进入 Git。
- 数据连接中断、跨库关联错误或索引写入失败时，保留上一批完整可用索引并明确提示。停止原型服务即可撤回运行入口；清理由原型创建且明确标记的数据库和索引前，单独核对目标。
