## Context

同步由 `server/sync.ts` 的单进程锁执行。页面只在打开时读取一次同步状态。点击「同步数据」成功后，用这次同步的返回结果更新状态，不另设定时读取。

## Goals / Non-Goals

让正在使用搜索页的人直接发起一次完整同步。同步入口只有页面按钮和命令行。不增加定时同步、定时读取状态、增量同步或开关式的持续同步。

## Decisions

按钮放在现有同步状态条，详情页也能看到。请求使用 `POST /api/prototype/sync`，服务端调用现有 `syncRecords`，成功返回与状态接口相同的结果。按钮在请求返回前禁用；另一路同步占用锁时返回已有的「已有同步任务运行」。失败响应后页面再读一次状态，以展示保留的上一批数据和失败原因。当前搜索结果不因同步成功而自动重查。

## Risks / Trade-offs

真实数据全量同步需要数秒到十几秒，这段时间按钮保持「正在同步」。接口只监听本机，与现有原型接口相同，不另加登录。
