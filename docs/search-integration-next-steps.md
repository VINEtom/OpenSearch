# OIS 全局搜索集成验收

下一步是在能连接 PMS 和 EMR 的集成环境同步真实数据，先验收 OpenSearch 字段筛选，再用同一批单据对照 BERT 和 BGE 的效果。本地无法直连 EMR 的同事可以在集成环境网页参与验收。

## 1. 部署新版并同步

1. 在集成环境部署包含定位字段和模型接入的 GitHub `main` 版本（至少包含提交 `c9821b4`）。
2. 按 [环境变量示例](../.env.example) 配置 PMS、EMR 和 OpenSearch。第一轮先设置 `SEARCH_MODELS=off` 并启动搜索后端。
3. 在同一部署环境执行 `SOURCE_MODE=real npm run sync`。打开搜索页的同步状态，确认本次同步成功并记录批次和时间。新版同步会从 EMR 分别读取 `imaging_modality_key` 和 `scan_site_list`。旧快照缺少这两列，直接导入旧快照无法补齐。
4. 请业务验收人在 EMR 选出可核对的单据。至少准备一张 CT 头部单、一张 CT 其他部位单、一张非 CT 头部单，以及同为 CT 的俯卧和仰卧单。记录内部单据编号供回查。

## 2. 先验收字段筛选

从网页全局搜索选择「全部记录」，用新批次执行下表查询，并用 EMR 原单核对结果。

| 查询 | 通过标准 |
| --- | --- |
| 定位方式是 CT | 显示「成像方式 · CT」，命中的定位申请单原字段为 CT |
| 定位部位是头部 | 显示「定位部位 · 头部」，命中的定位申请单原字段包含头部 |
| 定位方式是 CT 且定位部位是头部 | 显示两个条件，同一张单据同时满足。仅正文提及 CT 或头部的单据不命中 |
| 旧快照缺少字段时输入上述条件 | 显示识别条件和重新同步提示 |

## 3. 在同一批次验收模型

1. 把 BERT 微调权重和 BGE reranker 权重交付到搜索后端所在机器。配置 `SEARCH_BERT_PYTHON`、`SEARCH_BERT_MODEL_DIR`、`SEARCH_BGE_PYTHON` 和 `SEARCH_BGE_MODEL_DIR`，取消 `SEARCH_MODELS=off`，重启后端。依赖及目录格式见 [README](../README.md)。
2. 输入「找成像方式为 CT、备注里说要趴着摆位的定位申请单」。确认页面保留 CT 筛选，BERT 核对成功时显示标记。已进入同一候选页的俯卧单应排在仰卧单前，并显示能核对的原文片段。
3. 用同一查询关闭模型复跑，比较单据集合、前几条排序、相关片段和响应时间。分别记录首次加载和再次查询的耗时。模型关闭后仍须正确按 CT 筛选。

## 4. 记录结果并决定下一步

记录同步批次、查询、实际结果、排序和耗时，并区分「单据没进候选页」与「同页排序不理想」。字段错误先回查 EMR 源值和同步投影。若相关单据经常进不了候选页，再评估 BGE 向量召回。当前 BGE 重排只调整同一页已有候选。

本地 Chrome 已用虚构单据验证字段筛选、模型排序和关闭模型后的回退。真实数据验收待集成环境执行。
