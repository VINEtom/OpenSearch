# OIS 全局搜索集成环境接入守则

首批接入 PMS 患者、EMR 诊断和计划申请单，用真实来源验证「最近三个月确诊鼻咽癌、处方不少于 20 次」从搜索到原始记录的链路。首批范围建议以这条链路为准。RVS 治疗计划和其他单据可按同一套守则接入。

## 1. 先约定源数据，再写接入代码

| 对象 | 请源系统方提供 | 集成时核对 |
| --- | --- | --- |
| PMS 患者 | 患者主键、放疗号、展示字段、可见范围、合并与停用标记 | 确认跨系统患者 ID 的对应关系。保留放疗号前导零，用稳定 ID 关联同名患者 |
| EMR 诊断 | 诊断主键、患者主键、诊断名称及编码体系与版本、确诊状态、确诊日期、作废标记 | 确认哪个字段代表确诊日期和确诊状态。核对源系统时区、缺失值及编码口径 |
| EMR 计划申请单 | 申请单主键、具体诊断主键、患者主键、处方分次数、删除与作废标记 | 确认分次数是单张有效申请单的处方值。多版本、补录、撤销和缺失分次数分别提供样例 |
| RVS 治疗计划 | 计划主键、申请单主键、患者主键、有效状态 | 通过申请单追溯具体诊断，核对整条关系属于同一患者 |

每个数据源先交付一份字段映射。逐字段标明源接口或表、字段路径、类型、单位、空值语义、目标字段和用途（筛选、全文检索、列表展示或详情回查）。同时记录增删改的读取方式、可用的变更游标或快照边界、同步频率和可接受延迟。字段语义尚不明确时，先由源系统方和业务方确认，再启用对应条件。

业务数据以源系统为准。索引保存搜索所需的最少字段，以及定位源记录的系统标识、对象类型和稳定主键。患者对照失败、诊断关联缺失或归属冲突时，记录原因并阻止受影响记录参与组合筛选。应阻断整批发布的错误与可隔离的数据缺陷，在接入前明确并设置验收门槛。

## 2. 按用途建索引，按权限回查

- 诊断名或编码、确诊状态和日期、处方分次数使用明确的字段类型。标题和经批准的正文进入全文索引。列表展示字段按需返回，详情以当前用户的权限从源系统读取。
- 组合筛选以同一条具体诊断为单位。一张有效申请单达到下限即可，分次数取其结构化字段。日期和分次数缺失时按未知处理。首批规则沿用原型语义，遇到与真实源系统口径不同的情况，先确认业务规则再修改。
- 患者搜索结果中的诊断和处方条件，也要受用户对相应业务记录的可见权限约束。若同一患者的两张申请单对用户可见性不同，原型按诊断汇总的全局最高分次数不能直接作为该用户的筛选依据。应在限定可见记录后比较分次数，避免通过患者命中、总数、高亮或分类计数暴露受限信息。
- 使用独立的集成配置、集群或索引命名空间和凭据。源系统接入账号使用只读、最小授权，索引写入账号与搜索账号分开。搜索请求由 OIS 后端鉴权，浏览器通过业务接口访问。按集成环境的数据授权范围选样，限制 Dashboards 的索引访问，日志与验收附件使用脱敏标识。

原型的本地 Compose 使用演示配置，数据库初始化、样例导入和现有集成测试会操作演示库。真实源接入应新增只读适配层，使用独立配置，不向真实库执行 `db:init`、`db:seed` 或当前会重置样例库的测试脚本。真实样本和凭据存放在集成环境允许的位置。

## 3. 先对账，再切换搜索流量

1. 用一批授权样本只读试采，逐条核对患者、诊断、申请单的关联和状态，并记录各源的读取边界。跨系统无法提供同一时点快照时，记录每个来源的截止位置，补齐读取期间的变化，再验证关联。
2. 用明确的 mapping 构建候选索引。按类型对比源记录数、成功入索引数、按规则排除数和失败数。用可回查的样本检查字段值、关联 ID 和权限条件，并验证删除、作废、患者合并及权限收回。
3. 有可靠变更游标时，先将候选索引追到约定的切换位置，核对更新和删除，再从该位置继续同步。重试按稳定文档 ID 更新，旧变更不能覆盖新状态。没有可靠游标时，使用约定周期的全量重建和对账，并公开更新延迟。通过验收后，用一次别名操作发布新索引。 [OpenSearch 别名操作](https://docs.opensearch.org/latest/api-reference/alias/aliases-api/)
4. 记录发布批次、源读取位置、失败项、更新时间和当前别名。源系统不可用或候选索引校验失败时，停止发布并告警。已上线的旧批次只有在仍满足权限和撤销要求时才继续使用或作为回退目标。无法确认时暂停受影响的搜索，避免旧索引恢复已撤回的数据。

## 4. 集成验收

使用真实浏览器、集成后端、授权的真实源接口和独立 OpenSearch。由业务方先给出脱敏样例的预期患者和原始记录标识，再与搜索结果逐项对照。

| 场景 | 通过标准 |
| --- | --- |
| 输入「最近三个月确诊鼻咽癌、处方不少于 20 次」 | 页面显示实际日期范围、确诊诊断和分次数下限。恰好 20 次的合格患者进入结果，同一患者只显示一次 |
| 处方分次数不足、缺失，或高分次申请单属于另一条诊断 | 患者不因该申请单进入结果 |
| 只有正文提及鼻咽癌、确诊日期越界或诊断已作废 | 患者不因该记录进入结果 |
| 从结果打开患者及关联诊断和申请单 | 原始记录的 ID、患者归属、诊断和分次数与预期一致 |
| 用不同权限的账号执行同一查询并访问原始详情 | 搜索结果、计数、高亮及详情均符合各自权限。验证撤权后旧结果和旧批次的访问 |
| 更新分次数、作废诊断、合并患者，或中断并重试同步 | 约定时间内反映业务变化。重试不重复建档，不发布残缺数据 |
| 搜索普通关键词「屏」和「屏气」 | 分别按预先核对的真实样例返回匹配记录并高亮 |

验收记录保留测试日期、索引批次、预期与实际结果、权限角色和同步延迟。接入验收以集成环境实测为准，原型的虚构样例验证可用于回归。
